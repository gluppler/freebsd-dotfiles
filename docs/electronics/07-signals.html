Pulse-width modulation

A digital pin can only be on or off, but switched fast enough its average can be anything in between. The duty cycle D is the fraction of each period spent on:

D=tonTVavg=DVS

Choose the frequency for the load: a few hundred hertz or more for LEDs, so they do not flicker on camera, and above 20 kHz for motors, so they do not whine. An RC low-pass filter with its cutoff well below the PWM frequency turns PWM into a steady voltage, a cheap DAC.

Spectra and the square wave

Any periodic signal is a sum of sines at multiples of its frequency, its harmonics. A square wave contains only the odd ones, falling as 1/k:

x(t)=4π∑k=1,3,5,…sin(kωt)k

This is why fast digital edges radiate interference far above the clock frequency, and why a square wave through a low-pass filter comes out rounded: the filter removes the upper harmonics.

Sampling and aliasing

An ADC measures a signal at regular instants, fs times a second. The samples capture everything below half that rate, the Nyquist frequency; anything above it is not lost but folded down, indistinguishable from a lower frequency.

fs>2fmaxfalias=|f−kfs|

So filter before sampling: an analog low-pass filter, an anti-aliasing filter, removes what is above fs/2 before the ADC sees it. The same effect makes wheels in films seem to turn backwards.

ADCs and resolution

An N-bit ADC divides its reference voltage into 2N steps. One step is the least significant bit, the LSB, the smallest change it can see:

LSB=Vref2Ncode=⌊VinLSB+12⌋

That rounding error behaves like noise, which limits the signal-to-noise ratio of a perfect N-bit converter to:

SNR=6.02N+1.76dB

Real converters fall short of their bit count: noise, offset and gain error each cost some. The effective number of bits is the SNR you measure turned back into bits. A DAC runs the other way, Vout=code⋅Vref/2N.

Smoothing readings

Sensor readings are noisy. A moving average of the last M samples divides the noise by M and delays the reading by about M/2 samples:

y[n]=1M∑k=0M−1x[n−k]

An exponential moving average needs no buffer. Each new sample pulls the average a fraction α of the way towards it; it is the digital twin of an RC low-pass filter:

y[n]=αx[n]+(1−α)y[n−1]α=ΔtRC+Δt

With α a power of two, firmware needs only a shift and an add. Keep the average scaled up, or the rounding loses the small steps:

/* Exponential moving average with alpha = 1/8; avg8 holds eight times the average. */
static int32_t avg8;

int32_t smooth(int32_t sample)
{
    avg8 += sample - (avg8 >> 3);
    return avg8 >> 3;
}

For readings with occasional wild spikes, such as an ultrasonic range finder, a median of the last three or five samples removes the spikes before averaging.

Transfer functions and stability

A linear system is described by its transfer function H(s), where s stands for differentiation: an RC filter is 1/(sRC+1), a capacitor 1/(sC). The values of s that make the denominator zero, the poles, decide how the system responds:

H(s)=Kτs+1H(s)=ω02s2+2ζω0s+ω02

A system is stable if every pole has a negative real part. Sampled systems use z=esT in place of s, and are stable if every pole lies inside the unit circle.

Feedback control

A controller compares the measured output y with the setpoint r and drives the plant, the motor or heater or arm, to shrink the error:

T(s)=C(s)P(s)1+C(s)P(s)

Feedback makes a system follow the setpoint, resist disturbances and tolerate an imprecise plant. Too much gain, with delays in the loop, makes it oscillate: the same instability as a pole crossing into the right half plane.

PID control

The PID controller, used in everything from ovens to drones, adds three terms: one proportional to the error, one to its integral, which removes any lasting error, and one to its rate of change, which damps overshoot:

u(t)=Kpe(t)+Ki∫0tedτ+Kddedt

Sampled every Δt seconds, the integral becomes a running sum and the derivative a difference. This code draws the graph below: it runs when this page is built.

def controller(kp, ki, kd, dt, low=-10.0, high=10.0):
    """A PID controller; step(setpoint, measured) returns the output."""
    state = {'integral': 0.0, 'last': None}

    def step(setpoint, measured):
        error = setpoint - measured
        # Differentiate the measurement, not the error: no kick when the setpoint jumps.
        rate = 0.0 if state['last'] is None else (measured - state['last']) / dt
        state['last'] = measured
        integral = state['integral'] + ki * error * dt
        out = kp * error + integral - kd * rate
        if low < out < high:  # anti-windup: stop integrating while the output is pinned
            state['integral'] = integral
        return max(low, min(high, out))
    return step


def simulate(kp, ki, kd, seconds=20.0, dt=0.01):
    """Step response of the plant 1/(s + 1)^3, three lags in a row, under PID control."""
    control = controller(kp, ki, kd, dt)
    x = [0.0, 0.0, 0.0]
    out = [(0.0, 0.0)]
    for n in range(int(seconds / dt)):
        u = control(1.0, x[2])
        x[0] += (u - x[0]) * dt
        x[1] += (x[0] - x[1]) * dt
        x[2] += (x[1] - x[2]) * dt
        out.append(((n + 1) * dt, x[2]))
    return out

To tune by hand: start with Ki=Kd=0 and raise Kp until the response is quick but rings; add Kd to damp the ringing; add a little Ki to remove the remaining error. The Ziegler–Nichols rule starts from the gain Ku at which proportional control just oscillates, with period Tu:

Kp=0.6KuTi=Tu2Td=Tu8Ki=KpTiKd=KpTd

For this plant Ku=8 and Tu=2π/3≈3.6 s, giving Kp=4.8, Ki=2.65, Kd=2.18: a fast rise, 90% in 1.5 s, but a peak of 1.52. Ziegler–Nichols is a starting point; most loops then need their gains reduced.
